# PicStore API Documentation

## Обзор

PicStore — это сервис для хранения и обмена изображениями с возможностью загрузки через файл или URL, тегированием и управлением видимостью. API предоставляет REST‑интерфейс для работы с изображениями, а также веб‑интерфейс для пользователей.

**Базовый URL**: `http://localhost:8080` (или другой, заданный через `SERVER_BASEURL`)

## Аутентификация

Аутентификация выполняется через SSO (single‑auth). Пользователь должен быть авторизован для доступа к защищённым эндпоинтам (группа `/i`). После успешного входа устанавливается JWT‑токен в куке `singleauth_token`.

### Эндпоинты аутентификации

| Метод | Путь | Описание |
|-------|------|----------|
| GET   | `/sso/auth`   | Перенаправление на страницу входа SSO |
| GET   | `/sso/login`  | Callback для обработки ответа от SSO (устанавливает куки) |
| GET   | `/sso/logout` | Выход (очищает куки) |

## Основные эндпоинты

### 1. Главная страница

### 2. Страница «О проекте»

**GET /about**  
Возвращает HTML страницы «О проекте».

**Ответ**: HTML (шаблон `about.html`)

### 3. Список публичных изображений (с пагинацией и фильтрацией по тегам)

**GET /posts**  
Возвращает HTML страницы с постраничным списком публичных изображений. Поддерживает фильтрацию по тегам (включая исключающие теги) и пагинацию.

**Параметры запроса**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `page`   | int | Нет          | Номер страницы (начинается с 1). По умолчанию 1. |
| `tags`   | string | Нет       | Строка тегов, разделённых пробелами. Тег с префиксом `-` означает исключение (например, `природа -зима`). |

**Примеры**:

- `GET /posts` — все публичные изображения, первая страница.
- `GET /posts?page=3` — третья страница.
- `GET /posts?tags=природа` — изображения с тегом «природа».
- `GET /posts?tags=природа -зима` — изображения с тегом «природа», но без тега «зима».

**Ответ**: HTML (шаблон `posts.html`) с объектом `posts` (массив изображений текущей страницы) и объектом `pagination` (общее количество страниц, текущая, предыдущая, следующая).

---

### 4. Автодополнение тегов

**GET /api/tags**  
Возвращает JSON со списком тегов, начинающихся с заданного префикса (игнорируя ведущий минус). Используется для подсказок при вводе тегов.

**Параметры запроса**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `prefix` | string | Нет       | Префикс для поиска тегов. Если начинается с `-`, минус игнорируется. |

**Пример**: `GET /api/tags?prefix=прир`

**Ответ**:

```json
{
  "tags": [
    { "tag": "природа", "count": 42 },
    { "tag": "природный", "count": 5 }
  ]
}
```

---

### 5. Просмотр отдельного изображения (публичного)

**GET /view/:y/:m/:d/:h/:filename**  
Возвращает HTML страницы просмотра изображения с навигацией (предыдущее/следующее) и возможностью скачивания файла.

**Параметры пути**:

- `y`, `m`, `d`, `h` — компоненты даты (год, месяц, день, час) в пути хранения файла.
- `filename` — имя файла.

**Параметры запроса**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `view`   | string | Нет       | Если равен `"file"`, возвращает бинарные данные изображения (скачивание). |
| `tags`   | string | Нет       | Теги для фильтрации списка изображений (определяет порядок навигации). |
| `key`    | string | Нет       | Ключ для расшифровки зашифрованного изображения. |

**Примеры**:

- `GET /view/2025/12/25/15/image.jpg` — HTML страница.
- `GET /view/2025/12/25/15/image.jpg?view=file` — скачивание файла.
- `GET /view/2025/12/25/15/image.jpg?tags=природа` — просмотр в контексте фильтра «природа».

**Ответ (HTML)**: шаблон `view.html` с данными изображения, ссылками `prev`/`next` и, если включена предзагрузка, URL‑ами `prevImageURL`/`nextImageURL`.

**Ответ (файл)**: бинарные данные с Content‑Type `image/*`.

---

### 6. Health check

**GET /health**  
Проверяет доступность базы данных и кэша. Используется для мониторинга.

**Ответ**:

```json
{
  "status": "OK",
  "db": true,
  "cache": true,
  "version": "1.0"
}
```

Если БД или кэш недоступны, статус меняется на `"degraded"` с кодом 503.

## Защищённые эндпоинты (требуют аутентификации)

Все эндпоинты в группе `/i` защищены middleware аутентификации. Дополнительно для некоторых операций (загрузка, удаление) требуется роль `publisher`.

### 7. Профиль пользователя

**GET /i**  
Возвращает HTML страницы профиля пользователя.

**Ответ**: HTML (шаблон `profile/index.html`)

---

### 8. Загрузка изображений

**GET /i/upload**  
HTML форма загрузки изображений (файл или URL).

**POST /i/upload**  
Принимает данные формы для загрузки одного или нескольких изображений.

**Параметры формы**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `type`   | string | Да         | `"file"` для загрузки файла, `"url"` для загрузки по URL. |
| `files`  | file[] | Нет*      | Массив файлов (при `type=file`). Можно также использовать поле `file` для одиночного файла. |
| `urls`   | text  | Нет*      | Текст с URL‑ами, разделёнными переносами строк (при `type=url`). Можно также использовать поле `url` для одиночного URL. |
| `is_public` | checkbox | Нет | Если отмечен, изображение будет публичным. |
| `tags`   | string | Нет       | Теги через пробел. |
| `encryption_key` | string | Нет | Ключ для шифрования изображения. Если указан, изображение будет зашифровано. |

*Примечание*: для множественной загрузки используйте `files[]` или `urls` (многострочный текст). Для обратной совместимости поддерживаются одиночные поля `file` и `url`.

**Пример (curl)**:

```bash
curl -X POST -F "type=file" -F "files=@image1.jpg" -F "files=@image2.jpg" -F "is_public=on" -F "tags=природа лето" http://localhost:8080/i/upload
```

**Ответ**: редирект на `/i/upload` с параметром `info` или `error`.

---

### 9. Список изображений пользователя

**GET /i/posts**  
Возвращает HTML страницы со списком всех изображений, загруженных текущим пользователем. Поддерживает фильтрацию по тегам и пагинацию.

**Параметры запроса**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `page`   | int | Нет          | Номер страницы (начинается с 1). |
| `tags`   | string | Нет       | Теги для фильтрации (с поддержкой исключающих тегов). |

**Ответ**: HTML (шаблон `profile/posts.html`) с объектом `posts` (отфильтрованный и постраничный список) и объектом `pagination`.

---

### 10. Просмотр собственного изображения

**GET /i/view/:y/:m/:d/:h/:filename**  
Аналогично публичному просмотру, но проверяет принадлежность изображения текущему пользователю. Добавляет ссылки для редактирования и удаления.

**Параметры** — те же, что и в публичном просмотре.

**Ответ**: HTML (шаблон `profile/view.html`) с дополнительными полями `prevImageURL` и `nextImageURL` для предзагрузки соседних изображений.

---

### 11. Обновление изображения (публичность и теги)

**POST /i/view/:y/:m/:d/:h/:filename/update**  
Обновляет метаданные изображения (публичность и теги). Требуется роль `publisher`.

**Параметры формы**:

| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| `is_public` | checkbox | Нет | Если отмечен, изображение становится публичным. |
| `tags`   | string | Нет       | Новые теги (заменяют старые). |

**Ответ**: редирект обратно на страницу просмотра с параметром `info` или `error`.

---

### 12. Удаление одного изображения

**POST /i/view/:y/:m/:d/:h/:filename/delete**  
Удаляет изображение. Требуется роль `publisher`.

**Ответ**: редирект на `/i/posts` с параметром `info`.

---

### 13. Массовое удаление изображений

**POST /i/posts/delete**  
Удаляет несколько изображений по их ID. Требуется роль `publisher`.

**Тело запроса (JSON)**:

```json
{
  "image_ids": [1, 2, 3]
}
```

**Ответ (JSON)**:

```json
{
  "message": "изображения удалены"
}
```

## Внутренние API (используются фронтендом)

### 14. Предзагрузка соседних изображений

Клиентский JavaScript использует данные `prevImageURL` и `nextImageURL`, возвращаемые в `profile/view.html`, для предварительной загрузки соседних изображений. Это улучшает отзывчивость навигации.

### 15. Навигационный контекст

Фронтенд поддерживает навигацию по кэшированному списку ID изображений (сессионный кэш). При переходе между изображениями используется API `GET /view/...` с параметром `tags` для сохранения контекста фильтрации.

### 16. A/B тестирование

Сервер поддерживает эксперименты (например, `navigation_prefetch`). Вариант эксперимента определяется на основе хэша userID и может быть переопределён через конфигурацию. Фронтенд может получать вариант через скрытое поле в HTML или отдельный API (в текущей реализации вариант зашит в логику сервера).

## Пагинация

Пагинация реализована на уровне БД с помощью `LIMIT` и `OFFSET`. Размер страницы по умолчанию — 10 изображений.

**Структура пагинации в ответе**:

```html
<!-- В шаблоне доступен объект pagination -->
{{ if .pagination.prev }}
  <a href="?page={{ .pagination.prev }}&tags={{ .tags }}">Предыдущая</a>
{{ end }}
<span>Страница {{ .pagination.cur }} из {{ .pagination.total }}</span>
{{ if .pagination.next }}
  <a href="?page={{ .pagination.next }}&tags={{ .tags }}">Следующая</a>
{{ end }}
```

## Фильтрация по тегам

- Теги разделяются пробелами.
- Тег с префиксом `-` означает исключение (например, `природа -зима`).
- Фильтрация применяется как к публичным изображениям (`/posts`), так и к личным (`/i/posts`).
- Для фильтрации используется SQL‑запрос с условиями `IN` и `NOT IN`.

## Graceful Degradation

При недоступности Redis кэш временно отключается с помощью circuit breaker. Методы, использующие кэш, автоматически переключаются на прямые запросы к БД. Health‑чек (`/health`) отражает состояние кэша.

## A/B тестирование

В системе зарегистрирован эксперимент `navigation_prefetch` с вариантами:
- `control` — предзагрузка отключена.
- `prefetch` — предзагрузка соседних изображений.
- `aggressive` — агрессивная предзагрузка (окно из 5 изображений).

Вариант определяется на основе userID и может быть переопределён в конфигурации. Логика эксперимента влияет на генерацию ссылок `prevImageURL`/`nextImageURL`.

## Ошибки

Ошибки возвращаются в виде HTML страниц (шаблон `error.html`) или редиректов с параметром `error`. Для JSON‑эндпоинтов ошибки имеют вид:

```json
{ "error": "описание ошибки" }
```

Возможные коды ответов:

- `200` — успех.
- `400` — неверный запрос.
- `401` — неавторизован.
- `403` — нет прав (например, не publisher).
- `404` — изображение не найдено.
- `500` — внутренняя ошибка сервера.
- `503` — сервис деградировал (недоступна БД или кэш).

## Версионирование

Текущая версия API — `1.0`. Версия указывается в health‑чеке.
